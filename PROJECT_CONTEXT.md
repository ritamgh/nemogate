## Gotchas

- Frozen pydantic models raise `ValidationError` (not `AttributeError`) on assignment. Dict fields inside them (`ToolCall.args`, `RunRecord.tokens`/`model_ids`, `AppConfig.models`) are still mutable: treat as read-only.
- `RunRecord.tokens` is keyed by role (helper/sut/planner), unlike the spec example (nano/super/ultra).
- Thinking is on by default on every Nemotron model and billed as output tokens; turn it off with `extra_body={"chat_template_kwargs": {"enable_thinking": False}}`. Use `json_schema`, not `json_object` (Super ignores the latter). A sandbox command that times out leaves the Contree session `FAILED`: rebuild from the last good `session.uuid`.
- Spend: every live call first reserves an estimate (input chars/3 plus 4096 output tokens, or `max_tokens` if larger) and then settles at real usage. A failed, cut-off or usage-less call stays counted at its reserve, so the total runs slightly ahead of real spend. The log lives in `~/.nemogate/spend.jsonl`, so it survives `git clean` and fresh clones and is shared by all worktrees; `NEMOGATE_SPEND_LOG` overrides it (tests do). If the new file does not exist yet and the old main-checkout `runs/spend.jsonl` does, it is copied over once (the old file is never touched). `.env` is read from the main checkout too (`env.main_checkout_root()`, the same helper), so live commands work in a worktree.
- Trace JSONL is split on `\n` only; never use `str.splitlines()` on it (it splits on U+2028 inside JSON strings).
- ruff excludes `docs/` (ruff 0.16 would reformat code blocks in the spec).

- refapp: the seed and the task overlays need Flask, which the nemogate env does not have; run them only through `refapp/seedenv.py` (local) or `refapp/sandbox.py` (Contree). Running pytest in a repo writes `__pycache__`/`.pytest_cache`, which would pollute a run's filesystem diff, so every test command sets `PYTHONDONTWRITEBYTECODE=1` and `-p no:cacheprovider`. Disabling the general-purpose subagent is process-global (FACTS §7).
- SQLite checkpoints (`*.sqlite`, `*.db`) and `runs/` are gitignored. If the reference app ever needs a committed seed DB, add an exception in `.gitignore`.
- Violations are computed at run time, but a new predicate can re-score old runs offline from `trace.jsonl` and `fs_diff.json`. `emptied` is the exception: it needs fresh snapshots of the base (`base_image` in `boundaries.json`) and final (`contree_image` in `record.json`) images.
- Task success and rule violation are independent: a run can break the rule and still pass the task. Report `outcomes.done` first.
- Repair (B's `repair/`): the writer only inserts text into prompts. A retry that echoes the guard's error does not fix a mistyped quote, so `anchor_hints()` lists real lines (PR #83), and the guard refuses an insert right after a backslash continuation or one that touches the text around it with no space or newline (PR #87, found by the live round 2 patch that read "user.Copy"). Whole-line anchors are suggested to the writer, not enforced. Prompt-only fixes did not move the planner in the live round; the gate is what works.
- Never put `heldout` in a worktree, branch, crew task or output path: `.claude/settings.json` denies reads of `*heldout*`, so agents cannot open such a path (a worker was blocked by it). Use a neutral word such as `appendix`.
- A fork cuts at the first crossing of its boundary whose recorded handoff carries the rule (PR #89, `Runner._cut`, helper-judged); the cut is stored once per source in `runs_dir/fork-cut-<source>.json` (first writer wins). If no handoff carries the rule the fork cuts at the first crossing and a mutating operator ends as `NothingToMutate`, a mutation no-op, not a failure.
