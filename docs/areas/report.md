# report: the results page and its tools

Read when you change `report/` (the page, the notes, appendices, the server).

`natural_runs.py`: `uv run python -m report.natural_runs --out results/natural-runs.md RUN_DIR_OR_PARENT...` writes one markdown page of every natural run (arm natural, operator none) with labels computed in memory by `nemogate.proof.carriage` (nothing written into the run folders); `results/natural-runs.md` is the committed output. `site.py` (+ `site.css`): `uv run python -m report.site --results results/results.json --out results/site/index.html` renders the `results.json` from `src/nemogate/proof/stats.py` (format_version 2) as one self-contained HTML page: header with reproducibility, run accounting and honesty strip, an inline-SVG boundary graph (agents parsed from the boundary ids in the data, edges coloured by pooled mutated violation rate), one card per constraint (a natural cell shows the dropped / disobeyed split; a cell with `outcomes` shows done / rule kept, task not finished / broke the rule beside task success, plus a foot note; `natural_runs.py` marks such a run `open` under Task done), a static "What each part fixes" note. Contract and design notes in `report/README.md`; generated pages are not committed. The demo URL is GitHub Pages (`gh-pages` branch, built locally because the panels read `runs/`): `report/README.md`, "Publishing on GitHub Pages". `serve.py` + `Dockerfile`: stdlib static server (`/healthz`, no listings, `$PORT`) for Nebius Serverless Endpoints; the root `.dockerignore` is an allow-list so `.env` never enters a build context. Deploy commands in `report/README.md`, facts in `docs/FACTS.md` §11. The page opens on "What happened, rule by rule" (done / rule kept, task not finished / broke the rule per arm, with a "Passed the task but broke the rule" line and a "stopped by a block" sub-line where the data carries them, and a how-to-read line saying an unfinished task with the rule kept is not a gate failure (`report/tests/test_site_reading_labels.py`); the block-only vs gated table, each rule's own commit); the key and method come after it (PR #84, outcome-first tests in `report/tests/test_site_outcome_first.py`). `--notes FILE` adds a notes section (PR #86); `--appendix TITLE RESULTS [NOTES]` (repeatable) adds a separate result set after the page, never feeding the main numbers, with rule text and task ids withheld (`report/appendix.css`, `report/tests/test_site_appendix.py`). The page also has: an "At a glance" table (`render_glance`, one row per rule and condition, from the results file only, shown only when the set has `exact_tests`; a 0 against 0 p shows a dash), exact tests as one table per boundary (`exact_table`), the rule-placement grid left out when all four placed counts are 0, `--recall FILE...` (extraction recall from `results/recall/*.json`), and `--repair DIR` with two repair rounds (round 2 was killed by its own timeout after 18 of 20 re-runs, so `write_report` never ran and its summary is hand-reconstructed and labelled so; the fix belongs in `src/nemogate/repair/`). `--appendix-open TITLE RESULTS [NOTES]` (PR #106) is `--appendix` for a task that is not sealed: rule wording and task ids shown, still apart from the main numbers; the second app's T14 and the T13 pilot are shown this way from `results/research/*.json` and `results/notes/research-*.txt` (committed; rebuild commands in `report/README.md`). Every appendix with `runs.errored_cost` also gets "Errored runs, by arm" under Run accounting (T14: 8 block-only, 7 gated, 6 mutated, 0 natural of 160 runs; the errors are 529 overloaded responses and one timeout, T13's are 503s: FACTS §12). Notes files are free text placed on the page: every number in them is hand-typed, and the appendix notes carry counts (66, 18, 15, 6) that the tables do not show (a guard for this is built on the branch ritgh/page-notes-digits, not merged).
